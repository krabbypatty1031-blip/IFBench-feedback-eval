# IFBench 反馈修订实验协议

状态：**正式生成与量化分析已完成，320 条评分已完成人工审核。** 本文现行研究重点为输出结果的约束遵循和内容质量，不以成本或输出上限作为研究约束或评价指标。已有实验的原始冻结配置、划分、提示及评分口径仍以 `runs/feedback_eval/official/freeze.json` 为历史记录（`feedback-eval-official-hkbu-v1`，`freeze_sha256=a333e677…`）；本文的后续调整不追溯改变该冻结或已生成的结果。模型为 HKBU GenAI `gpt-4.1` / `gpt-4o`。

本文只定义研究问题、数据和评分口径。日常命令见 [运行手册](feedback_eval.md)；阶段验收见 [执行计划](EXPERIMENT_EXECUTION_PLAN.md)；目录职责见 [结构设计](ARCHITECTURE_PLAN.md)。

## 目标与贡献

研究规则验证器反馈能否改善模型对输出约束的遵循，以及这种改善是否伴随内容质量退化。复用 IFBench 官方数据、验证器及评分；自主实现模型适配、配对修订、反馈生成、记录和分析。研究是基于公开方法的实验与工程扩展，不预设方法优于现有方法。

## 数据和固定版本

- 基础版本：IFBench `cd189a9c2889526d8af901d2103fd3e1ffcea6df`。
- 数据：`data/IFBench_test.jsonl`，SHA-256 `d2ada7da94a38cfe406351614c4e686846ed2da6d1b339db95fa5ead19554a4a`，300 条、58 种约束。仓库另一副本存在两条提示词尾部空格差异，整个实验不得混用。
- 候选划分：40 条开发、260 条测试；先核验重复题、潜在同源任务，按组划分，尽量覆盖约束类型和单/双约束。若发现组数量使配额不可行，记录实际配额。划分脚本固定种子、输出 ID 和哈希，冻结后测试集不用于调整提示。公开测试集和模型训练数据的独立性未知，不能宣称无污染或结果代表自然用户分布。
- 在开发阶段先核验具体约束、提示文本和验证器结果能否一一对应；无法可靠生成约束反馈的题目须预先定义处理规则并报告，不得依照实验结果挑选。

## 条件与运行

同一模型同一题生成一份初始回答 B0。以相同原题、初始回答和对话结构独立运行各修订条件，各一次额外调用，不串联分支，不向模型暴露其他组结果：

| 条件 | 增量反馈 |
| --- | --- |
| B1 | 通用检查和修订要求 |
| B2 | 通用要求加整体通过或未通过 |
| B3 | 通用要求加每条约束通过或未通过及题中对应的原始要求 |

无论 B0 是否通过都修订，以估计修复与退化。反馈内容须忠实于原任务和实际验证结果，不包含参考答案；对于没有可读约束映射或验证器异常的样本，不编造反馈，记录并根据开发阶段冻结的规则处理。B3 使用官方严格验证结果生成反馈；严格和宽松最终得分均报告，宽松分数不代表独立验证器。反馈组是模型加验证器的系统评估。

开发集编写并检查每组完整英文提示：均要求保持原任务内容、仅输出最终修订答案；B2/B3 通过时明确允许保持原样。固定消息结构、模型版本、温度和工具设置；记录实际生成设置及终止原因，以便解释和复现输出。不同模型不支持相同参数时记录实际设置，不暗示完全等价。测试前冻结完整模板并存档哈希。

## 评分与分析

- 主指标：官方 strict 提示级通过率（所有约束均通过）。附报 loose 提示级以及 strict/loose 约束级通过率；不得将 loose 称为人工认可。
- 修复率：B0 未通过且修订通过的题数除以 B0 未通过题数；退化率：B0 已通过且修订未通过的题数除以 B0 已通过题数。各自报告分子、分母及无可用分母情况。
- 配对比较各条件在相同题目上的差异，以题目或确认的同源任务组为重采样单位计算区间。单/双约束和类别结果属于探索性分析，样本少的类别报告计数与不确定性。
- 人工内容审核：预先固定随机抽取 40 个测试题，审核所有条件的回答，隐藏条件和模型身份并打乱顺序；依据原任务标记完成、部分完成或未完成，记录无法判断。核查主要内容与请求的相关性、完整性和明显错误；不同类别可能需要额外知识，不将审核结果当成全面事实核验。记录审核者、分歧处理和原始标注；若仅一人审核，明确说明无法估计评分者间一致性。
- API 错误、限流、截断、空回答、验证器异常分开报告，不伪装成模型失败或成功；记录重试及缺失数据规则，同时报告完成率和缺失情况。
- **已有结果的分析口径：** 使用当前合并后的结果进行量化分析、盲审和报告。原始运行中空正文或错误的身份，若后续补跑得到可评分正文，则使用恢复结果；原来成功的身份不替换，仍无正文的身份保持缺失。合并规则在正式运行后确定，补跑使用了不同生成设置，报告应简要说明这一来源及各项指标的分母；原始记录保留以供追溯。

## 执行阶段与边界

1. 离线验证官方样例与 58 种约束的依赖、严格/宽松结果、反馈映射和重复 ID；仅有开发数据参与开发。
2. 两个可用模型的小规模开发试验，检查输出、失败率与区分度。260 × 2 × 4 = 2,080 个身份为正式实验的预期输出规模。
3. 依据开发结果确定模型、完整提示、数据分组和评分规则；若验证器不能可靠反馈，缩小到预先定义且可验证的约束子集，并披露覆盖范围。若模型表现饱和，报告该设置区分度不足，不从测试结果挑选失败题。
4. 生成冻结记录后执行正式测试，保存原始响应、验证结果和审计数据；抽样人工审核并生成结果。正式 2080 个身份均有记录；量化表已重建；320 条评分已填写并经项目作者逐条人工审核确认。

正式实验使用 HKBU GenAI 的 `gpt-4.1` 和 `gpt-4o`（Azure 形状接口）。密钥只放在本地 `.env`。

## 已知环境事项

NLTK 资源位于 `ifbench/.nltk_data`。运行时设置 `NLTK_DATA` 为该目录绝对路径，避免导入时尝试联网下载。官方 `instructions_test.py` 在该设置下通过 71 项测试及 144 个子测试。代码生成脚本按提示文本续跑，实验扩展须使用题目 ID、模型、条件、轮次和协议版本建立独立身份并记录异常。
